# Newton 1.3 build spec: the read-only AD audit

Status: build spec, revision 2, 2026-11-08. Inputs: the AD persona's design decisions and `GAPS.md` (catalogue,
safety rules, ActiveDirectoryMCP take-list). Newton writes nothing to a directory in 1.3; every finding carries the fix
as text for the owner to run (Newton writes, scripts or explains a change by how reversible it is; 1.3 only
explains and scripts).

## 1. Shape

The owner runs a one-time setup script, generated by Newton and run as an admin. It:
- creates an ordinary domain user `newton-audit`;
- installs a fixed collector, its query set and the forbidden list on a collector host;
- pins Newton's public key to that user with a forced command.

The collector host is the DC on both platforms. On Windows a domain member can stand in (LVR-AD-01). On Samba the collector runs through a root helper behind one NOPASSWD sudoers line.

The collector takes **no input**. It runs the installed query set and prints one JSON document. Newton then:
- connects over SSH;
- validates the document against the contract (section 5);
- evaluates the checks in Python;
- returns findings through redaction and the untrusted envelope.

The Newton side uses no LDAP library and stores no directory password. The model never chooses a filter, a base or an attribute.

## 2. Why the collector takes no input

A root helper on Samba reads `sam.ldb` without ACLs. If it accepted filters or attribute names, a stolen
key could read password hashes, or use a filter as a blind oracle (ActiveDirectoryMCP defect D4). A
collector that runs only its installed query set cannot be steered.

The query set is pinned. The collector reports the SHA-256 of the exact `queries.json` bytes it ran. Newton refuses any document whose hash differs from its own copy, with the message "collector out of date: rerun the setup".

## 4. The query set (`queries.json`)

The file format:
```json
{"v": 1, "queries": [{"id": "...", "base": "...", "scope": "base|sub", "filter": "...",
  "attrs": ["..."], "binary": ["..."], "ranged": ["member"], "sd": false, "limit": 20000,
  "presence_only": false}]}
```

**`base`** is `{domain}`, `{config}`, `{schema}`, or a DN ending in one of those. The collector substitutes its own naming contexts.

**`sd: true`** adds `nTSecurityDescriptor` with the owner and DACL only (Windows `SecurityMasks = Owner, Dacl`; Samba control `sd_flags:1:5`), never the SACL. It is returned as base64. The collector asks for the attribute by name as well as with the control, because the real ldb returns only the attributes a search names (measured on the lab DC on 2026-11-08).

**`ranged`** lists the attributes whose values the collector must page through. On Windows this means a `member;range=N-*` loop on any row that returns a ranged attribute. On Samba the bindings return all values (LVR-AD-06).

**`presence_only`** queries have filters that test a forbidden attribute for presence, `(attr=*)`. They request `distinguishedName` and `objectSid` only. They are the one place a forbidden name may appear, and only on the attribute side of a filter.

**`limit`** is a hard cap. Hitting it marks the query `truncated`. The collector also stops a query at 8 MiB of serialized rows and marks it `truncated`.

**The 1.3 query set.** This table is the normative query contract. `D` = `{domain}`, `C` = `{config}`, `S` = `{schema}`, and every query requests `distinguishedName`.

The validator runs at build time and at load time, and each rule has a unit test:
- query ids are unique;
- every attribute matches `^[A-Za-z][A-Za-z0-9-]*$`, and none is `*`;
- no requested attribute is forbidden;
- outside `presence_only` queries, no attribute name on the left side of a filter term is forbidden (values such as `lDAPDisplayName=ms-Mcs-AdmPwd` are fine);
- filters are balanced and contain no `:=`;
- `limit` is at most 50000.

**FORBIDDEN_ATTRIBUTES** is normative as listed here. It is a deliberate superset (some names are unreal or legacy, which is harmless):
- **Password hashes and history:** unicodePwd, dBCSPwd, ntPwdHistory, lmPwdHistory, pwdHistory, supplementalCredentials.
- **Password-bearing attributes:** userPassword, unixUserPassword, msSFU30Password.
- **LAPS:** ms-Mcs-AdmPwd, msLAPS-Password, msLAPS-EncryptedPassword, msLAPS-EncryptedPasswordHistory, msLAPS-EncryptedDSRMPassword, msLAPS-EncryptedDSRMPasswordHistory.
- **BitLocker:** msFVE-RecoveryPassword, msFVE-KeyPackage, msFVE-RecoveryGuid, msFVE-VolumeGuid.
- **gMSA:** msDS-ManagedPassword, msDS-ManagedPasswordId, msDS-ManagedPasswordPreviousId.
- **KDS root keys:** msKds-RootKeyData.
- **Domain backup keys and trust secrets:** currentValue, priorValue, trustAuthIncoming, trustAuthOutgoing, initialAuthIncoming, initialAuthOutgoing.
- **Credential roaming:** msPKI-DPAPIMasterKeys, msPKI-CredentialRoamingTokens, msPKIAccountCredentials, msPKIRoamingTimeStamp.
- **Key credentials:** msDS-KeyCredentialLink.

Deliberate deltas from ActiveDirectoryMCP's `SENSITIVE_FILTER_ATTRIBUTES`:
- `nTSecurityDescriptor`, `securityIdentifier`, `sIDHistory` and `msDS-AllowedToActOnBehalfOfOtherIdentity` are **not** forbidden. They hold SIDs and owner+DACL descriptors, not secrets, and the checks need them.
- `ms-Mcs-AdmPwdExpirationTime` and `msLAPS-PasswordExpirationTime` are not forbidden. They hold times, which are the LAPS deployment signal.

`forbidden.py` is the single source. `setupgen.py` writes `forbidden.json` beside each installed collector. At start, each collector loads both files and refuses to run (exit 2, fixed message) if any requested attribute, or any non-presence filter attribute, is forbidden.

## 5. The collector document (the collector contract)

```json
{"v": 1, "collector": "windows", "collector_version": "1.3.0", "querysetsha": "<hex of queries.json bytes>",
 "is_dc": true,
 "domain": {"dns": "win.newton.test", "domain_dn": "DC=win,DC=newton,DC=test",
            "config_dn": "CN=Configuration,DC=win,DC=newton,DC=test",
            "schema_dn": "CN=Schema,CN=Configuration,DC=win,DC=newton,DC=test", "domain_sid": "S-1-5-21-..."},
 "identity": {"user": "newton-audit", "sid": "S-1-5-21-...-1105", "token_group_sids": ["S-1-5-21-...-513", "S-1-5-11"]},
 "started": "20261108T120000Z", "elapsed_ms": 812,
 "queries": {"users": {"status": "ok", "error_code": "", "rows": [{"dn": "CN=...", "a": {"sAMAccountName": ["x"]}}]}},
 "files": {"gpp":     {"status": "ok", "error_code": "", "items": [{"gpo": "{31B2F340-016D-11D2-945F-00C04FB984F9}",
                       "path": "Machine/Preferences/Groups/Groups.xml", "kind": "cpassword", "count": 1}]},
           "gpttmpl": {"status": "ok", "error_code": "", "items": [{"gpo": "{...}", "section": "Kerberos Policy",
                       "key": "MaxTicketAge", "value": "10"}]}},
 "settings": {"status": "ok", "error_code": "", "items": [{"source": "registry",
              "key": "HKLM\\SYSTEM\\CurrentControlSet\\Services\\NTDS\\Parameters\\LDAPServerIntegrity",
              "status": "ok", "value": "1"}]}}
```

**Status values** (one table, used by queries, files, settings and settings items):

| status | meaning |
|---|---|
| `ok` | read completed |
| `truncated` | limit, byte budget or deadline hit |
| `denied` | access denied, reported by the server |
| `unsupported` | object class or feature absent on this platform |
| `unavailable` | server down or the path does not exist |
| `not_collected` | this collector host cannot read it (e.g. settings off-DC) |
| `error` | anything else |

**Error codes:** `error_code` is `""` when the status is `ok`. Otherwise it is one of `access_denied`, `no_such_object`, `size_limit`, `time_limit`, `byte_limit`, `unsupported`, `server_down`, `not_a_dc`, `parse_refused`, `other`. Exception text never appears.

**Value encoding:** both collectors encode values identically, which is what makes one catalogue work.
- Every value is a JSON string, and multi-valued attributes keep directory order.
- `binary` attributes and `nTSecurityDescriptor` are standard base64 of the raw bytes.
- Integers, including large integers, are decimal strings.
- GeneralizedTime is written as `YYYYMMDDHHMMSS.0Z` in **UTC**. PowerShell 5.1 returns local `DateTime`, so the Windows collector calls `.ToUniversalTime()`; a fixture test covers this.
- Booleans are `TRUE`/`FALSE`.
- An attribute the directory did not return is absent from `a`.

**Fixed lists:**
- `queries` keys equal the query-set ids exactly; an extra or missing id is a hard error.
- `settings` items are exactly the fixed list in section 7 for the collector of the document (each key once, with the source of that collector), with item-level `status`; there is no in-band sentinel value. A `settings` section whose status is not `ok` carries no item.

**`files.gpp`** carries only:
- the GPO folder name, emitted only if it matches `^\{[0-9A-Fa-f]{8}(-[0-9A-Fa-f]{4}){3}-[0-9A-Fa-f]{12}\}$`; anything else is skipped and counted in `skipped_nonguid`;
- a relative path, built from fixed directory and file names only;
- a kind (`cpassword` or `autologon`) and a count.

It never carries a value, a username or file content. The scrub happens on the DC.

**`files.gpp` and `files.gpttmpl`** also carry the counts of the scan, both optional and zero by
default:
- `parse_refused`: the files that were read and could not be used (a file that does not parse, a
  file that is too big, a key of a template that no check reads and a value of a key that is not a
  number);
- `skipped_special`: the entries that were never read (a symlink, a named pipe, an entry past a cap
  of the walk).

A file section that refused or skipped files is not the whole of the data, so a check that reads
it may not answer PASS: it is UNKNOWN with the reason `parse_refused`. A finding that was read
stays a finding.

**`wire.py`** validates everything above, plus:
- a maximum document size of 64 MiB;
- a maximum value length of 64 KiB;
- no forbidden attribute name anywhere in `a`;
- no NUL in any string;
- `identity.sid` present and a valid SID;
- `token_group_sids` a non-empty list of valid SIDs.

Any violation is a hard error for the whole audit (`collector document invalid: <fixed reason>`), never a partial report.

## 6. Results model

- `Status`: `PASS`, `FINDING`, `UNKNOWN`. A check that cannot prove PASS is UNKNOWN.
- `UnknownReason`: `access_denied`, `unsupported`, `unavailable`, `truncated`, `not_collected`, `error`,
  `parse_refused`.
  A query or file status other than `ok` maps directly to the same-named reason for every check that uses it.
- **Sentinels** (empty read = could not read): `domain_head` has 1 row; `users` contains RID 500 and RID 502
  (by SID, never name); `groups` contains RIDs 512 and 513; `computers` contains at least one row with
  `primaryGroupID` 516; `adminsdholder`, `dir_service`, `partitions`, `schema_head`, `dc_ou` have 1 row;
  `protected_sds` contains RID 500 and RID 512; `ous`, `fsps` and `optional_features` are not empty. A
  failed sentinel makes every dependent check `UNKNOWN(access_denied)`. Every query a check reads, the
  principal lookups of its membership walk included, declares its sentinel, unless it is one of the
  queries below that an ordinary user may see empty, `trusts` or `schema_laps`, whose empty read is the
  answer (no trust; no LAPS attribute in the schema), or a query the check judges itself: `gmsa` in
  AD-A-23 and `gpos` in AD-A-52, AD-A-54 (UNKNOWN when empty) and AD-A-55 (names only).
- **Queries an ordinary user may legitimately see empty** (`psos`, `kds_root_keys`, `dpapi_backup`,
  `gmsa`, presence queries): empty is reported as `UNKNOWN(access_denied)` with the note "none visible to
  the audit account", never as PASS, unless the collector is Samba (root reads all; empty is a real
  empty). LVR-AD-05 measures which are readable on Windows.
- **Required attributes:** each check lists the attributes every readable object always has (e.g.
  `objectSid`, `userAccountControl`); if any in-scope row lacks one, that check is `UNKNOWN(access_denied)`.
  Optional attributes (`servicePrincipalName`, `adminCount`, ...) absent means not set.
- `Finding`: check id, severity (`low|medium|high`), title, affected objects (each: SID or GUID formatted
  from binary, plus name and DN as untrusted strings, plus the decoded evidence), `maps_to` (references; the
  words "compliant"/"non-compliant" never appear), `fix`.
- `AuditReport`: domain, collector, counts by status and severity, per-check results, `generated`, and
  `scope_note` (configured state only; event-based evidence not collected; the deferred list; "an ordinary
  account cannot see objects hidden by list-object mode or per-object ACLs", tied to AD-A-43).

## 7. Collectors

Common to both:
- **Input:** takes no arguments and never reads stdin.
- **What it runs:** every query in the installed `queries.json`, the SYSVOL scan and the fixed settings list.
- **Output:** exactly one JSON document on stdout. Exit codes:
  - 0 when a document was produced, even if some queries failed;
  - 2 on a forbidden-list refusal or an unsafe install;
  - 1 when no document can be produced.
- **Paging and time limits:** page size 500; 30 s server time limit per query; 300 s deadline for the whole run. When the deadline passes, every remaining query or file is marked `truncated` with `time_limit`, and the document is still printed.
- **XML:** every file is first refused if it contains `<!DOCTYPE` or `<!ENTITY` (`parse_refused`), then parsed with DTD processing off. On Windows that is `XmlReaderSettings.DtdProcessing = Prohibit`; on Samba it is the stdlib `xml.etree.ElementTree`, safe after the pre-check. A `cpassword` is never matched by regex over raw text.

**Windows (`collector.ps1`, PowerShell 5.1, no RSAT):**
- **Reading AD:** `System.DirectoryServices.DirectorySearcher` against `LDAP://<this DC or the PDC>/<base>`. `byte[]` becomes base64, `Int64` a decimal string, and `DateTime` is converted `.ToUniversalTime()` to GeneralizedTime. `member` is read in ranges.
- **Identity:** `WindowsIdentity.GetCurrent()`, its `User` and `Groups` SIDs.
- **Install:** the collector, `queries.json` and `forbidden.json` go in `C:\ProgramData\Newton\ad\`. The ACL there is Administrators and SYSTEM full control, and `newton-audit` read and execute, with no inheritance from the parent. At start the collector refuses (exit 2) if any of the three files, or the directory, grants write, modify or full control to any SID other than Administrators (S-1-5-32-544), SYSTEM (S-1-5-18) or TrustedInstaller.
- **Settings:** on a DC only (otherwise `not_collected`). HKLM values, missing = item `unavailable`:
  - `SYSTEM\CurrentControlSet\Services\NTDS\Parameters`: `LDAPServerIntegrity`, `LdapEnforceChannelBinding`
  - `SYSTEM\CurrentControlSet\Control\Lsa`: `LmCompatibilityLevel`, `NoLMHash`, `RestrictAnonymous`
  - `SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0`: `RestrictSendingNTLMTraffic`, `RestrictReceivingNTLMTraffic`
  - `SYSTEM\CurrentControlSet\Services\Netlogon\Parameters`: `RestrictNTLMInDomain`, `FullSecureChannelProtection`, `VulnerableChannelAllowList` (presence only: value `"present"`)

  Keys are written in full as `HKLM\SYSTEM\...\Name`.
- **SYSVOL:** under `\\<dns>\SYSVOL\<dns>\Policies\<GUID>\{Machine,User}\Preferences\`:
  - every `*.xml` is scanned and elements with a non-empty `cpassword` attribute are counted;
  - in `Registry.xml`, `DefaultPassword` or `AutoAdminLogon` entries are counted as `autologon`.

  Under `<GUID>\Machine\Microsoft\Windows NT\SecEdit\GptTmpl.inf` (UTF-16), the sections `[System Access]`, `[Kerberos Policy]` and `[Registry Values]` are read; from the last, only the registry keys in the settings list.
- **Run as:** sshd `Match Group` on a group the setup creates for `newton-audit` (LVR-AD-02 confirms the spelling), plus `ForceCommand powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File C:\ProgramData\Newton\ad\collector.ps1`.

**Samba (`newton-ad-samba`, python3, distribution samba bindings):**
- **Reading AD:** `SamDB(url=<private dir>/sam.ldb, session_info=system_session(), lp=LoadParm())`. `nTSecurityDescriptor` is asked for by name and comes with the control `sd_flags:1:5`: the real ldb returns only the attributes a search names, so the control alone does not bring the descriptor (measured on the lab DC on 2026-11-08). The bindings return raw bytes, which are base64'd; LDIF from `ldbsearch` is never used (it rewrites SIDs and descriptors as strings).
- **Run as:** `sudo -n /usr/local/sbin/newton-ad-samba`, forced by `authorized_keys` `restrict,command="sudo -n /usr/local/sbin/newton-ad-samba"`. It rejects any argument, and the sudoers line allows it none: `newton-ssh ALL=(root) NOPASSWD: /usr/local/sbin/newton-ad-samba ""`.
- **Login account (measured 2026-11-08):** the SSH login is a LOCAL account `newton-ssh`, not the domain account. On a Samba DC with `passwd: files winbind`, winbind already resolves the domain `newton-audit` (shell `/bin/false`), and `useradd newton-audit` fails with "already exists". So the local name must differ.
- **Identity:** `SUDO_USER` must be exactly `newton-ssh`, otherwise exit 1. The identity reported is the domain account `newton-audit`: its `objectSid` and `tokenGroups` from sam.ldb. If that lookup fails, the run exits 1.
- **Install:** the helper is root-owned 0755 at `/usr/local/sbin/`. `queries.json` and `forbidden.json` are root-owned 0644 in `/usr/local/lib/newton-ad/`. It refuses (exit 2) if any of them, or their directories, is group- or other-writable or not owned by root.
- **Settings:** `LoadParm().get(name)`, for exactly `ldap server require strong auth`, `ntlm auth`, `server signing`, `server min protocol`, `kerberos encryption types`, `allow nt4 crypto`, `reject md5 clients`, `server schannel`, `tls enabled`. The build confirms each name exists in 4.22, and that it governs the AD DC, not just that testparm prints it; it drops and reports any that do not.
- **SYSVOL:** `<sysvol path>/<realm lower>/Policies`, parsed the same way. The walk is done by descriptor: the base is opened with `O_DIRECTORY | O_NOFOLLOW`, every folder is opened relative to the descriptor of its parent and every file relative to the descriptor of its folder, so no path string is opened below the base and a name that is swapped for a link is never followed. A file is opened with `O_NOFOLLOW | O_NONBLOCK` and must be a regular file. The walk is bounded (10000 entries in one directory, a depth of 8) and the deadline is checked before every directory and every file. Only the keys of a template that the checks read are emitted, and only when their value is a number: a key that no check reads is dropped silently, and a key that is read and whose value is not a number is counted in `parse_refused`. Every case variant of the folders that hold the template is read, the way the walk reads every case variant of the folder of a scope: two variants that hold a key with the same value emit it once, and two that do not agree on it emit neither value and are counted once in `parse_refused`.

## 8. Checks for 1.3

Every check is a pure function, `evaluate(doc) -> CheckResult`, and declares:
- `id`, `title` and `severity`;
- the queries it uses and its required attributes;
- `maps_to` and `fix`.

Privilege is computed by **SID/RID**, never by name (defect D5).

`members.py` resolves membership recursively and cycle-safely (D6, AD-A-03 "cycles"; there is a cyclic fixture), including `primaryGroupID` (AD-A-04) and foreign security principals.

**The privileged set:** the domain RIDs 512, 516, 518, 519, 520, 521, 498, 526 and 527, plus the BUILTIN groups S-1-5-32-544, 548, 549, 550 and 551, plus everything nested in any of them.

**Identity guard (always first, regardless of the `checks` argument):** Newton finds `identity.sid` in `users` and computes that account's recursive privileged membership itself, including `primaryGroupID`, from the directory data. It does not trust the token alone. The audit stops with "this key is a privileged account; Newton refuses to audit with it" when any of these holds:
- the account is RID 500;
- it is in the privileged set;
- it holds a privileged token SID;
- it cannot be found in `users`.

**Checks** (GAPS ids):
- **The account checks** (`checks/accounts.py`):
  - account and Kerberos flags: 01, 02, 03, 04, 05, 06, 07, 08, 09, 10 (presence; LVR-AD-05), 11, 12, 13 (attribute set and the SIDs inside it; who can write it is in 52), 14, 16, 17, 18, 19;
  - 20: password attributes present, no description scan;
  - 21, 22, 23 (LDAP part; KDS keys created, never their data), 24, 25, 26, 27, 30;
  - 31: name patterns `MSOL_*`, `AAD_*`, `AZUREADSSOACC$`;
  - 32: Windows only; Samba is `UNKNOWN(unsupported)`.
- **The domain checks** (`checks/domain.py`):
  - 33, 35, 43, 44, 45, 46;
  - 34: from the `gpttmpl` of the GPOs in `domain_head.gPLink`;
  - 36, 37, 38: configured state from `settings` plus the DC-linked GPOs, labelled "configured; observed not collected";
  - 48: inventory, `trustAttributes` and encryption types;
  - 55: cpassword and autologon presence;
  - 60: FSMO owners;
  - 67: LDAP half, `operatingSystem(Version)` of DC objects.
- **The ACL checks** (`checks/acl.py`, with `secdesc.py`):
  - 51: DCSync rights on the domain head, from the extended-right GUIDs `1131f6aa-9c07-11d1-f79f-00c04fc2dcd2`, `1131f6ad-9c07-11d1-f79f-00c04fc2dcd2` and `89e95b76-444d-4c62-991a-0facbeda640c`, expanded through groups. Allowed holders are excluded: RIDs 512 (Domain Admins) and 519 (Enterprise Admins), which Windows grants all extended rights on the domain head by default (measured on WINDC1, 2026-11-08), 516, 521, 498, BUILTIN 544, S-1-5-9 (Enterprise DCs) and SYSTEM. An ACE with CONTROL_ACCESS and no object type is all extended rights, so it counts. Known limit: 519 and 498 are built from the audited domain's SID, so in a child domain (where they carry the forest root's SID) they give a false FINDING, never a false PASS.
  - 52-core: GenericAll, WriteDacl, WriteOwner, GenericWrite, or WriteProperty on `member`, `servicePrincipalName`, `msDS-KeyCredentialLink`, `msDS-AllowedToActOnBehalfOfOtherIdentity` or `scriptPath` (all-properties included), held by principals outside the privileged set. Checked on `domain_head`, `adminsdholder`, `protected_sds`, `dc_ou` and the `gpos` linked at the domain head or the DC OU.
  - 53: AdminSDHolder drift, i.e. the same write rights for non-privileged principals.
  - 54-ACL: GPO DACL and owner write rights for non-privileged principals. File ACLs and version drift come later.
  - 57: who other than the privileged set holds read or control on `BCKUPKEY_*`.
- **Deferred, written into the scope note:** 15, 28, 29, 39-42, 47, 49, 50, 54 (file half), 56, 58, 59, 61-66, 67 (host half), 68-80, 82, 83, and AD CS. GAPS rule 11 (FullLanguage) is retired: there is no JEA, and the forced command is the boundary.

**Fix text (the owner runs it):** every FINDING has `fix.windows` and `fix.samba`. Each is a short explanation, the commands, what they change, and how to put it back.
- **How objects are named:** commands identify objects only by a SID or GUID that Newton formatted from the binary value, e.g. `Set-ADAccountControl -Identity 'S-1-5-21-...-1107' -DoesNotRequirePreAuth $false`. On Samba, `ldbmodify` takes the `<SID=S-1-5-...>` DN form.
- **Directory strings:** a directory-originated string never appears inside a command; it sits beside the command, in the envelope.
- **Execution:** Newton never runs a fix.

### Known limits of the 1.3 checks (from the check reviews, 2026-11-08)

- A gPLink to a GPO that was deleted or lives in another domain keeps AD-A-52 and AD-A-54 at UNKNOWN until the
  link is removed: conservative, never a false PASS. The scope note should say so.
- AD-A-55 does not yet report `skipped_nonguid` SYSVOL folders.
- The identity guard (a privileged audit key is refused) does not see a key that is privileged only through a
  group the audit account cannot read. AD-A-03/05/06/09 report such groups as UNKNOWN.
- Deferred from the account checks: an expected-key-credential allow-list for AD-A-10 (Windows Hello for Business
  domains are noisy), delegation set on user service accounts for AD-A-12 (needs `msDS-AllowedToDelegateTo` in
  the users query), Cert Publishers and DnsAdmins in the AD-A-03 inventory.
- Samba: when these limits were written, no check had yet run on a Samba document.

## 9. MCP surface and setup

- **Inventory:** a device entry with `platform = "ad-windows"` or `"ad-samba"`, plus `host`, `user` (`newton-audit` on Windows, the local `newton-ssh` on Samba), the key, `domain` and the pinned host key, as vendor devices have.
  - `adapters/registry.py` gains both platforms with a read-only capability. Its tool set is the AD tools only: no getters, no router tools, no writes.
- **Transport:** `vendor_ssh.py` gains `FORCED_COMMAND_PLATFORMS = frozenset({"ad-windows", "ad-samba"})`, alongside `CLI_SHELL_PLATFORMS`.
  - These platforms require an empty remote command **and** empty stdin, and refuse anything else.
  - A test covers both directions; the existing junos rule is unchanged.
  - stdout is capped at 64 MiB; the timeout is 360 s.
- **Tools:**
  - `newton_ad_audit(device, checks?: list[id])` returns the report, rendered through redaction and the envelope.
  - `newton_ad_list_checks()` returns id, title, severity, platforms and the deferred list.
  - Neither takes a filter, a base or an attribute.
- **Key flow:** Newton generates the key pair with the same key store and permissions the vendor enrolment uses. The setup script embeds the **public** key only. The private key never appears in any script or output.
- **Setup:** `scripts/newton-ad-setup windows|samba --domain ... --collector-host ... --device <name>` prints the owner's setup script (PowerShell or bash) for them to read and run as an admin. The script:
  - creates `newton-audit` with Domain Users only and a random password generated inside the script and never shown (on Samba the primary group of the account is checked, never changed);
  - creates the sshd match group (Windows) or the authorized_keys entry and the local login account `newton-ssh` (Samba);
  - checks the directories of the install and installs the files with the section 7 ownership; a file whose content is right is installed again when its owner or its mode is wrong;
  - writes the sudoers drop-in of the account last (Samba), so that a run which stops before it leaves no sudoers file behind;
  - finally prints the inventory entry.

  It never asks for, prints or stores a password.
- **Skill text:** the `newton-ad` part of `SKILL.md` is written by the maintainer, not generated with the code.

## 10. Tests and proof

Unit and contract tests (no network) cover:
- the query-set hash and the validator: one generated test per forbidden name, in attrs and in filters, plus the presence-only exception;
- `wire.py`: one test per malformed shape, including ids, statuses, identity, sizes and a non-GUID GPO name;
- `forbidden.json` generation;
- `secdesc.py` on measured descriptors;
- `members.py` on a cycle, a primary-group member and an FSP;
- each check's PASS, FINDING and UNKNOWN paths;
- the sentinel and required-attribute rules;
- the identity guard: RID 500, nested DA, primary group 512, a missing identity;
- fix commands: a property test with hostile names (`'`, `"`, `;`, `$()`, backticks, newlines, unicode quotes) shows no directory string inside any command;
- the envelope wrapping every directory string;
- no secret in any rendered report;
- a hostile `Groups.xml` (entity expansion) refused.

**Fixtures:** only documents **measured** from the lab collectors. Variants are made by editing a measured document in a test helper, and each names its source file.

**Live proof (lab only):**
- every seed in the lab's seed list (not shipped) is FOUND on both domains, and an unseeded snapshot has no FINDING for the seeded ids;
- the planted cpassword value is absent from the document, the report and the transcript (grep);
- a key for a Domain Admins member is refused;
- an ACL-denied read yields UNKNOWN, not PASS (LVR-AD-03).

## 11. Order

1. The core (sections 3 to 6, minus checks and collectors: the `queries.json` from the section 4 table,
   `forbidden.py`, `wire.py`, `values.py`, `secdesc.py`, `members.py`, the runner with the identity guard,
   `render.py` and the `vendor_ssh` forced-command mode) and the two collectors (the Windows collector,
   `collector.ps1`; the Samba collector, `newton-ad-samba`) do not depend on each other. The collectors take `queries.json` and
   `forbidden.json` from this spec's table, verbatim, as test inputs.
2. **Measure:** install both collectors in the lab by hand and run them on the seeded domains. Also run them under
   an ACL-denied account and under a privileged account. Save the documents as fixtures and fix any contract drift.
3. The checks (the account, domain and ACL checks, which share the descriptor code) and the MCP surface
   (inventory, tools, transport wiring, `setupgen.py`, `newton-ad-setup`) build on the measured fixtures.
4. **Then:** a cold review of the whole, the live proof, and the maintainer approves before release.

## 12. Lab-verified-required items

- **LVR-AD-01:** an ordinary domain user can log on to a Windows DC over OpenSSH with a key. If not, the collector host is WINMEMBER1 and `settings` is `not_collected`.
- **LVR-AD-02:** the exact `Match` spelling Windows OpenSSH uses for a domain user or group. With it, `ssh <key> newton-audit@dc whoami` prints the collector document, not `whoami`.
- **LVR-AD-03:** a read denied by ACL returns empty rows silently on both collectors, and the sentinel rule turns that into UNKNOWN.
- **LVR-AD-04:** the Samba 4.22 bindings return raw bytes for `objectSid` and for `nTSecurityDescriptor` when the attribute is asked for by name (with `sd_flags:1:5`), and `tokenGroups` resolves.
- **LVR-AD-05:** which of `psos`, `kds_root_keys`, `dpapi_backup`, `gmsa`, `msDS-KeyCredentialLink` and `userPassword` presence an ordinary user can read on Windows.
- **LVR-AD-06:** `member` ranged retrieval. A seeded group with 1600 members comes back complete on both collectors.
